# 成员 C：购物车与订单模块需求规格

## 1. 基本信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 校园鲜达 |
| 负责人 | 成员 C |
| 需求基线 | `demo-v0.3`（提交 `84aa763`） |
| 模块范围 | 购物车、订单确认、订单创建、库存扣减、订单查询、集成执行和演示 |
| 上游依赖 | 成员 A 提供登录用户和收货地址；成员 B 提供有效商品、价格、库存和演示数据 |
| 下游依赖 | 组长汇总集成结果、缺陷证据、报告和演示材料 |

## 2. 目标与边界

本模块为登录用户提供加入购物车、修改购买数量、选择商品结算、确认收货信息、生成订单、扣减库存和查询历史订单的闭环，并保证用户权限、金额和库存数据一致。

本阶段不接入真实支付平台、退款、物流查询、优惠券、发票和复杂促销。订单中的支付状态仅作为演示字段保留。

## 3. 参与者与前置条件

- 登录用户：管理自己的购物车，使用自己的收货地址创建并查看订单。
- 商品模块：提供有效商品、当前价格、当前库存和商品状态。
- 系统：负责服务器端校验、金额计算、事务处理和数据隔离。
- 用户必须登录后才能访问购物车、订单确认和订单历史；创建订单前至少存在一个有效收货地址。

## 5. 业务规则

1. “当前用户”以服务器登录会话为准，浏览器传入的用户编号不能作为权限依据。
2. 购物车条目、地址和订单的读取或修改必须同时校验其所有者为当前用户。
3. 有效销售商品必须未被逻辑删除、所属分类有效且库存大于 0。
4. 订单总额等于所有订单明细小计之和加配送费；所有金额使用十进制数并保留两位小数。
5. 订单明细中的单价是下单时的价格快照，不随商品表后续变化。
6. 库存不足属于业务失败，系统必须保证失败前后的订单、库存和购物车数据一致。

## 6. 异常与质量要求

- 所有写操作必须在服务器端校验登录状态、数据所有权、商品状态、数量和库存。
- 非法参数、越权访问和重复请求不得导致其他用户数据变化，也不得向普通用户泄露调试信息。
- 购物车数量和金额变化应及时反馈，订单提交期间应防止用户误操作造成重复提交。
- 订单关键操作应保留足够的日志信息，便于定位失败环节，但日志不得记录密码等敏感信息。
- 页面应沿用“校园鲜达”的名称、标志和绿色视觉风格，并保持主流程按钮和错误提示清晰可见。
